# 奖学金材料审核工作台

把学生交上来的 Word 申报材料自动拆开，**把奖项条目和证明图片自动对上号**，
输出一份可以直接看的审核页。全程在本机运行，材料不出电脑。

---

## 它解决什么

学生的材料常见四种毛病：

1. 奖项名统一列在正文，图片全部堆在板块末尾（甚至自己在标题里写"（证书在下面）"）
2. 奖项名干脆不写，只写在证书图片上
3. 一段话里塞好几个奖项，后面跟好几张图
4. **图片和奖项对不上**——最严重的是竞赛板块里混进了奖学金证书、等级证书

人工审核要在脑子里建立"哪个奖对应哪张图"的映射，这就是耗时的大头。

本系统**完全不看图片在文档里的位置**，只按内容做全局配对。所以上面四种毛病
对它是同一个问题、一套算法。堆叠的文件反而更好处理。

## 两套读图通道：本地 OCR 与视觉大模型

系统支持两种读图方式，结果按图片指纹缓存，可以混用：

| | 本地 OCR（RapidOCR） | 视觉大模型（VLM） |
|---|---|---|
| 运行位置 | 本机 CPU，离线 | 需要模型服务 |
| 输出 | 一堆文字行 | 结构化字段（奖项名/等级/学年/落款/人名/指标） |
| 艺术字体、印章遮挡 | 基本读不出 | 能读 |
| 名单里找某个人 | 做不到 | 能做到 |
| 隐私 | 图片不出本机 | 图片需送出 |

**在胡珍华的 33 张图上实测**（见 `out/识图对比_胡珍华.md`）：

- 本地 OCR 自评"高可信"的只有 16 张，而且其中不少是**高信错误**——
  比如一张证书读出来只剩"荣誉证书 同学：荣誉称号 特发此证"，自评却是 high
- 视觉大模型在同一批图上，奖项名全部读对：
  `后航创老先五作` → **创新创业先进个人**；
  `200-20场 学年优本学生` → **优秀学生（2022-2023）**；
  `优秀学生主部 7072-2024` → **优秀学生干部（2023-2024）**；
  `文明劳身学生汽进个人` → **文明修身学生先进个人**

### 怎么接入视觉模型

1. 视觉模型读完后，按 `vision.py` 的 `SCHEMA` 写成 JSON，
   放进 `cache/vision/<图片 sha256>.json`
2. 引擎自动优先使用视觉结果，没有的图片回退本地 OCR
3. 参考实现见 `engine/seed_vision_huzhenhua.py`（胡珍华 32 张图的完整读取结果）

所以可以**渐进式接入**：先把读不准的图交给视觉模型，其余仍走本地。

## 判定规则（这些是审核真正的判断逻辑）

| 规则 | 说明 |
|---|---|
| **级别判定** | 落款含完整校名"湖州师范学院/湖州师范大学"→ 校级；剔除完整校名后仍有"XX学院"→ 院级；含"浙江省"→ 省级；含"全国/教育部"→ 国家级。**院级材料不能算校级** |
| **学年简写展开** | 学生写"2022-2024学年省政府奖学金"，系统自动展开成 2022-2023 与 2023-2024 两学年，各自配图 |
| **证据形式多样** | 证书 / 名单公示 / 汇总表截图 / 成绩单 / 系统截图**都算有效证据**，不因为"不是证书版式"就忽略 |
| **名单类匹配** | 名单公示表里找申报人姓名，找到即通过（比"姓名唯一"宽松，因为名单天然含多人） |
| **以图反推** | 条目描述不全或找不到图时，用图上读到的奖项名反推，在页面标注 |
| **等级考试核验** | 四级/六级总分 ≥425 判通过；普通话二级乙等及以上判达标 |
| **跨位纠正** | 原位置放错的证书，系统在别处找到正确的那张，标蓝提示确认 |
| **资格硬门槛** | 从成绩排名表核绩点、排名、不及格门次 |

## 配对结果怎么读

| 颜色 | 含义 | 你要做什么 |
|---|---|---|
| 🟢 自动配对 | 证据充分（赛事名归一后一致 + 等级/年份/姓名吻合） | 扫一眼即可 |
| 🔵 跨位纠正 | 文档里紧邻它的那张图不是它，系统在别处找到了正确的 | **确认一下**——这是系统替你改的 |
| 🟡 待确认 | 多个候选分数接近，或证据链不完整 | 你判断 |
| 🔴 缺图 | 没有任何图片达到阈值 | 通知学生补 |
| ⚪ 声明无材料 | 学生自己在条目里写了"（无材料）" | 正常，不算异常 |

另外会单独列出**无归属图片**：有图但归不到任何奖项——往往意味着**学生漏写了奖项名**。

## 配对是怎么算出来的

分四步，只有第二步花钱：

1. **拆解** —— 本地解析 docx，抽出奖项条目、证书图片、板块结构。零成本。
2. **读图** —— 本地 OCR 把证书读成文字，再抽成结构化字段（证书类型、赛事名、等级、
   年份、获奖人）。按图片 SHA256 缓存，同一张图永远只读一次。
3. **打分** —— 条目 × 图片全量笛卡尔积。三层信号：
   - 板块先验（"学科竞赛"板块就该出现竞赛证书，出现奖学金证书要扣分）
   - 内容匹配（赛事名归一到 A 类名单标准名后比对、奖项短语、等级、年份）
   - 姓名核对（个人证书要求姓名匹配；名单类截图要求申报人出现在名单里）
4. **分配** —— 匈牙利算法求**全局最优**，而不是逐条找最像的。
   贪心会抢图（A 抢走 B 唯一能配的图），全局最优不会。
   同时允许"不匹配"：每条奖项可以配一个虚拟的"我没找到图"。

## 本地 OCR 与云端复核

按"本地先试、不行才上云"设计：

- 本地用 RapidOCR（ONNX，纯 CPU，离线），证书图片**不出本机**
- 每张图会给一个可信度评估
- **只有"本地读不准 且 没配上对"的图才建议送云端视觉模型复核**——
  已经配对成功的图没必要再花钱（实测可把上云量压掉三成）

## 已知边界

- **浮动图片（`<wp:anchor>`）** 在 Word 里没有可靠的段落位置。实测有学生 26 张图
  全是浮动图。本系统只看内容不看位置，所以不受影响——但也因此**不提供"图片在文档哪一页"的定位**。
- **艺术字体、印章遮挡、低清照片** 的证书，本地 OCR 会读不准，会标记"建议云端复核"。
- **手写签名、盖章** 无法验证真伪，仍需人工。
- 身份以**文件名**为准；文档内标题只作交叉校验（实测有学生标题里还是上一届的班级号、
  甚至还是 `xxx` 占位符）。


## 读取层：已全面转为视觉大模型

- 图片识别**全部走视觉大模型**，187 张图 100% 覆盖，结果按 `sha256` 缓存在 `cache/vision/`。
- `engine/config.py` 的 `ALLOW_OCR_FALLBACK = False`：视觉模型没有结果的图会明确标成
  "待视觉复核"，**不会**用本地 OCR 的结果悄悄顶替——这是减少误判的关键开关。
- 逐张读图后写缓存：`engine/apply_vision_batch.py`
  （输入 `_batch_in.json`，键是 `学生名__imageN.ext`，值是该图的结构化字段）。
- `engine/vision.py` 定义字段约定，并负责按落款判定国家级/省级/校级/院级。
- 新增/更新材料后，只要没读过的图会出现在"待视觉复核"里，读完后重跑即可。

## 配置与流水线（阶段 0B）

### 所有阈值/权重/词表都在一个文件里
`engine/rules_builtin.json` —— 唯一事实源，共 83 项可配置：

| 分组 | 内容 |
|---|---|
| `weights` | 打分权重（类型 22、赛事名 38、等级 12、级别 10、年份 8、姓名 6、三重命中 15 …）|
| `thresholds` | 配对门槛 50、自动确认 80/60、备选接近 12、参考名单相似度 0.7 … |
| `vocab` | 奖学金/荣誉/技能/体测/志愿/科研 短语表、通用词屏蔽表、LCS 停用词 |
| `regex` | 等级、年份、赛事名（全称+简称）、板块标题 |
| `sections` | 板块期望语义 / 期望证据形式 / 顺序 / 序号映射 |
| `semantic_keys` | 语义分类关键词（reading 用）|
| `sem_labels` | 语义展示名（匹配理由里显示用）|
| `level_rules` | 国家级/省级/校级/院级的落款词表 |
| `reading_rules` | 四级 425、普通话等级、**体测 75** |
| `triage` | 图片分诊阈值（长宽比 6、过小 180/400、异常 2.6）|

改这个文件即可调整判定规则；也可以用代码覆盖：

```python
from settings import DEFAULT
cfg = DEFAULT.with_overrides({'reading_rules.physical_pass': 70,
                              'thresholds.match': 45})   # 返回新对象，不改默认
```

`engine/gen_rules.py` 是当初"从活代码导出这份 JSON"的工具，留着备查。

### 流水线拆成了可独立调用的步骤
`engine/pipeline.py`：

```python
r   = step_parse(docx)              # 解析（纯本地，快）
mf  = step_media_manifest(r)        # 图片清单 + 分诊
rd, todo = step_readings(mf, cfg)   # 读缓存，返回"还差哪几张要读"
#   ← Web 层在这里调视觉模型，把结果写回 cache/vision/<sha256>.json
r, items, imgs, ignored, res, labeled = analyze(docx, comp_items, ref, cfg)
```

读图（要联网、慢）和配对（纯本地、快）彻底分开，这是 Web 层能做进度条、
能中断重跑、能按 sha256 复用缓存的前提。

### 改造期的"零差异"守护
`engine/verify_diff.py`：

```bash
python verify_diff.py baseline   # 改造前存基线
python verify_diff.py check      # 改造后逐字段比对，有差异就退出码 1
```

本次重构（8 个模块 + 新增 3 个模块）全程保持 **result.json 与基线逐字段完全一致**，
即"改造不改变任何结论"。

## 关键设计

### 1. 引擎不联网
所有大模型调用都在 `web/services/vision_client.py`，读完写回
`cache/vision/<sha256>.json`。引擎照旧只读缓存，因此：
- 已有的 187 张读图缓存**零成本复用**（实测：黄俊杰 26 张图全部命中）；
- 引擎仍可脱离 Web 单测；同一张证书跨批次只读一次。

### 2. 读图与配对分离
`pipeline.py` 把流程拆成 `step_parse → step_media_manifest → step_readings
→ analyze`。读图（联网、慢、可中断）和配对（纯本地、秒级）彻底分开，
所以 Web 层能做进度条、能断点续跑、能只重跑配对（改了规则后不必重读图）。

### 3. 队列用 DB 任务表，不引 Celery/Redis
`tasks` 表 + 原子 UPDATE 认领 + 独立 worker 进程。宝塔上少维护一个服务，
任务状态天然可查询（进度轮询直接读表）。worker 崩了有 `requeue_stale()` 放回队列。

### 4. 绝不把半成品写进缓存
视觉模型返回的 JSON 要过归一化校验（枚举归一、人名去重、metrics 转数值、
敏感字段丢弃）才允许 `put`。非法 JSON 会**带着错误信息纠正重试一次**，
仍失败则记 `invalid` 并保留原文，绝不污染引擎读到的数据。

### 5. 人工判定覆盖引擎结论
`match_states`（确认/否定/改派）与 `orphan_adoptions`（未认领图采纳为条目）
在渲染层叠加到引擎结论上，引擎输出保持不变 —— 原始判定可追溯、可一键撤销。

### 6. 规则可视化
`rules_builtin.json` 的 `thresholds / reading_rules / weights / triage`
做成面板（带中文解释）。改动写进 `rules_overrides` 表，用
`EngineConfig.with_overrides()` 生成批次配置，**不改动默认值**，可一键恢复。

## 隐私

- api_key 用 Fernet 加密存库，主密钥在 `data/instance/api_key.key`（权限 600）。
- 视觉模型返回时会丢弃 `id_card / phone / bank_card` 字段。

# 阶段 2：标准化 Word 导出（已完成）

## 解决什么问题

学生交上来的 docx 里，**奖项名和图片经常是错位、堆叠**的——好几张图挤在一起，
或者图跑到奖项名上面两页。辅导员核对时得来回翻。

导出把它重排成：

```
板块标题  →  奖项名（带序号）  →  紧跟其 ≥1 张证明图（居中、等比缩放）
```

顺序完全按**模板六大板块 + 引擎与人工的配对结论**重来，与原 Word 的排版无关。

## 实测效果

以黄俊杰为例（21 条目 / 26 图，原来图文堆叠最严重）：

| 项 | 结果 |
| --- | --- |
| 保留条目 | 21 条，**每条后面紧跟它的证明图** |
| 图片 | 24 张（正文 21 + 文末清单 3） |
| 板块顺序 | 一→六 与模板一致，断言通过 |
| 文末清单 | 2 条待确认（含反证原因）+ 3 张三/四/六级证书 |

整批次导出：13 份 docx 打包 33 MB，HTTP 下载正常。
文件名规范：`{班级号}_{姓名}_奖学金申报材料（标准化）.docx`。

## 实现要点

- **以模板 docx 为基底再清空段落**，页面尺寸(A4)、页边距(上下2.54/左右3.17cm)、
  默认字体天然继承，不必用代码重建版式。
  ⚠️ 清空时必须保住 `<w:sectPr>`——它挂在 body 末尾，删段落时极易一起删掉，
  删掉页面设置就全丢了。
- 图片宽度上限 = 实测可用宽度 **14.651cm**；同时**限高 20.5cm**，
  否则长截图（如 646×1437）会撑破页。
- 竞赛板块按级别自动分子标题：`（一）国家级 /（二）省级 /（三）校级及其他级别`。
- 只导出「已确定」的条目（green/blue/人工确认/人工改派/人工采纳）；
  待确认、缺图**统一进文末「待补充 / 待确认清单」**，附上反证原因，不混进正文。
- 同一奖项可带多张证明：正文里重复贴的图会被引擎判成「未认领」，
  但只要与该条目匹配度 ≥60 分，就一并挂到该条目下。
- 导出时**去掉学生原文自带的序号**，否则会出现「1. 1.省级：…」。

# 阶段 3：多奖学金项目 + MySQL（已完成）

## 为什么要「奖学金项目」

辅导员不只评国家奖学金，还有国家励志奖学金、省政府奖学金、校级奖学金、单项奖学金……
它们的**申报板块不同、阈值不同、导出模板也可能不同**。

如果把这些写死进代码，每加一个奖学金都要改引擎。所以引入「奖学金项目」这一层：

```
奖学金项目（programs）
├─ 板块方案   看哪些板块、顺序、显示名、是否必需
├─ 规则覆盖   只对本项目生效的阈值（如校级奖学金体测线不同）
├─ 模板 docx  导出标准化材料用哪套版式
└─ 参考材料   A 类竞赛表 / 成绩排名表，可绑定到具体项目
        ↓
批次（batches）→ 材料（files）→ 审核结论 → 导出
```

**引擎一行没改。** 引擎仍按学生文档的标题分类到一套「规范板块键」，
项目只决定「用哪些键、怎么展示、阈值多少」。新增奖学金 = 建一条记录 + 选一套板块方案。

### 预置方案

新建项目时可一键套用：国家奖学金 / 国家励志奖学金 / 省政府奖学金 / 校级奖学金 / 单项奖学金 / 其他。
建好后仍可逐项调整顺序、改名、勾选是否必需、增删板块。

### 验证（`tests/program_check.py`，20 项全过）

同一份学生材料分别放进「国家奖学金」和「校级奖学金」：

| 项 | 国家奖学金 | 校级奖学金 |
| --- | --- | --- |
| 审核页板块 | 竞赛 / **三、科研创新** / 五、体测 / 六、志愿者时长 | 竞赛 / **四、体测** / 五、志愿者时长 |
| 体测达标线 | 75（继承全局） | **70**（项目覆盖） |
| 导出 Word | 含「三、科研创新」 | 不含 |

并验证：项目级覆盖**不会污染全局**，也不会影响其他项目。

## 数据库：SQLite / MySQL 双引擎

`web/db.py` 里做了方言层，业务代码只写一种 SQL：

| 项 | SQLite | MySQL |
| --- | --- | --- |
| 占位符 | `?` | `%s`（自动翻译） |
| upsert | `ON CONFLICT(..) DO UPDATE SET x=excluded.x` | `ON DUPLICATE KEY UPDATE x=VALUES(x)` |
| 自增 | `INTEGER PRIMARY KEY AUTOINCREMENT` | `INT PRIMARY KEY AUTO_INCREMENT` |
| 索引长文本 | 可以 | 必须 `VARCHAR(n)` |
| 时间比较 | `datetime('now', ?)` | — （**统一在 Python 侧算好截止值再传参**） |

- 本地开发/自动化测试用 **SQLite**（零依赖、跑得快）
- 正式部署用 **MySQL**（多进程并发写更稳）

切换方式：环境变量 `WB_DB=mysql` 或项目根目录的 `.env`。

### 部署（宝塔 Linux）

```bash
# 1) 装依赖
pip install -r requirements.txt

# 2) 配好 .env（照着 .env.example 改）
cp .env.example .env && vi .env

# 3) 建库建表 + 自检
python tools/init_db.py
python tools/init_db.py --check

# 4) Web 进程（宝塔「Python 项目管理器」）
gunicorn -w 3 -b 127.0.0.1:8000 wsgi:app

# 5) 读图 worker（宝塔「守护进程」）
WB_INLINE_WORKER=0 python worker.py
```

> 生产环境务必把 Web 进程的 `WB_INLINE_WORKER` 设为 0。否则读图跑在 Web 进程里，
> gunicorn 一重启就打断任务。

**从 SQLite 迁到 MySQL**（本地调通后上线，不想丢数据）：

```bash
python tools/init_db.py --db mysql --host ... --user ... --password ... --database ...
python tools/migrate_sqlite_to_mysql.py --host ... --user ... --password ... --database ...
# 文件不在数据库里，把 data/uploads/ data/images/ data/results/ data/instance/ cache/ 一起拷过去
```

### 老库自动迁移

`CREATE TABLE IF NOT EXISTS` 不会给已存在的表补列，所以启动时会跑一次幂等迁移
（`db.migrate()`）：补 `batches.program_id` / `refdata.program_id` / `refdata.note`，
并把 `rules_overrides.key/value` 改名为 `rule_key/rule_value`。
顺序是**建表 → 补列/改列 → 建索引**（索引建在列之前会失败）。

`/profile` 可以自助修改。忘记密码时：`python tools/init_db.py --reset-admin`。

# 阶段 4：自定义规则（自然语言）+ 隐私遮挡 + 部署文档

## 一、自然语言规则：编译期可调模型，运行期纯函数

辅导员的口径常常是一句话：「省级竞赛不认院级证书」「国家级竞赛证书必须能核对到获奖人」。

如果直接让大模型在审核时判定，会出两个问题：**同一份材料跑两次结论可能不同**、
**没法解释也没法复现**。所以拆成两段：

```
编译期（Web 层，允许调模型）     中文 ──► 受限 DSL（JSON）──► 白名单校验 ──► 回显确认
运行期（engine/rules_engine.py） DSL × 材料事实 ──► 效果列表（纯函数、零网络、零随机）
```

### 防幻觉的四道保险

1. **白名单校验**：DSL 里的字段/操作符/动作必须是目录里有的，发明一律拒绝。
   目录：15 个字段、12 个操作符、5 个动作（penalty / bonus / status / note / require_person）。
2. **运行期零 LLM**：`evaluate_facts()` 是纯函数，不联网、不随机、不读时间。
3. **排序确定**：`priority desc, id asc`，结果可复现。
4. **命中可追溯**：审核页会显示「命中了自定义规则」并列出改了什么，
   扣分也会出现在「反证」里。

### 影响预览（确认规则最有效的手段）

编译完不等保存，先拿**已有的审核结论**试跑一遍：

> 会影响 **3** 条已审条目：
> 薛婉婷 · 获2025年大学生创新创业训练计划项目…省级立项　　amber → amber（-50 分）

比读 DSL 直观得多。

### 作用域

- **全局规则**（`/rules`）：所有奖学金都生效
- **项目规则**（`奖学金项目 → 自定义规则`）：只对该奖学金生效，同 id 覆盖全局版

### 实现中的两个关键约束

- **规则事实必须落盘**。`result.json` 里的条目原本只有 `{id,section,text}`（没有 `sig`），
  而真实流水线里条目带 `sig`。如果预览从 JSON 重新推算事实，就会和实跑不一致
  （踩过：预览说"没影响"、实跑却改了状态）。现在 `analyze_one` 会把
  `rules_engine.build_facts()` 的结果一并落盘，预览和实跑走同一个求值器。
- **级别取值必须确定性**。`item.sig.levels` 是 `set`，而 Python 字符串哈希每进程加盐，
  **直接遍历 set 会得到不稳定的结果**——同一份材料两次运行可能得出不同级别。
  必须按固定的 `LEVELS` 顺序取。

## 二、送模型前的隐私遮挡

成绩单、四六级成绩单、计算机等级证书上常带身份证号，这些图片会以 base64 送给外部模型。

`web/services/privacy.py`（**纯本地**，图片不出本机）：

```
RapidOCR 拿到每行文字的坐标框 → 正则识别身份证/手机号/银行卡/学号 → PIL 涂黑那个框
```

- **默认关闭**，在「模型设置」里一键开关（也可用 `WB_MASK_SENSITIVE=1`）
- 另外提供「检查一张图会被遮什么」：上传图片→只报告会遮哪些号码，不落盘
- **只改送去模型的那份字节**，落盘的原始图片不动（人工复核仍看得到原图）
- 缓存里标 `masked: true` + 遮挡记录落日志，避免"某天开了遮挡、结果对不上"时无从判断
- 任何异常都退回原图 —— 绝不能因为遮挡失败就读不了图

实测（真实证书，含身份证号 450403200311083642）：遮挡后 OCR **再也读不出该号码**，
而不含敏感信息的图**字节完全不变**（不做无谓重编码）。
